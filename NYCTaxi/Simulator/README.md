# NYC Taxi Price-Acceptance Simulator (`beta_simulator`)

This package builds and serves a **passenger price-acceptance simulator** for NYC
taxi rides. It is the *environment* used by the online-pricing experiments in
the parent repository: given an offered price and the contextual features of a
trip, the simulator returns a (stochastic) **accept / reject** decision.

> **Full experiment pipeline.** Training happens here (`load_data_with_map.py` →
> `beta_simulator.py` → `simulator_response.py`). Out-of-sample testing on
> December 2014 NYC TLC yellow+green data is in [`../2014_data/README.md`](../2014_data/README.md).
> See also the [repository overview](../README.md).

The acceptance model is a logistic regression trained on **augmented** data:
every real trip becomes a *positive* example (the actual fare was accepted), and
synthetic *negative* examples are generated by offering inflated prices
(`typical_fare × multiplier`) that a rational passenger is assumed to reject.
A configurable label-noise rate flips some rejects back to accepts to stress-test
robustness.

## ⚠️ Data availability & citation

The **raw training data is NOT included** in this repository. It comes from a
Kaggle competition whose rules do not permit redistribution. To (re)train the
simulator you must download it yourself and accept the competition rules.

**Source dataset — Kaggle, *New York City Taxi Fare Prediction*:**

> <https://www.kaggle.com/competitions/new-york-city-taxi-fare-prediction>

Download `train.csv` from the competition's *Data* tab and place it in this
folder as `Simulator/train.csv` (a `train.csv.zip` next to it also works — the
loader auto-detects either).

**Time window used.** Although `train.csv` spans 2009–2015, the pre-trained
artifacts shipped here are built from the **2013-12-01 to 2014-11-30** slice
(12 months). `load_data_with_map.py` time-filters while reading, and the
resulting processed file is `2013_4_Trained_nyc_taxi_data_with_directionality.csv`
(the default `--processed-data-path` of `beta_simulator.py`).

> **Note on the dataset.** The code consumes the columns
> `fare_amount, pickup_datetime ("YYYY-MM-DD HH:MM:SS UTC"), pickup_longitude,
> pickup_latitude, dropoff_longitude, dropoff_latitude, passenger_count` and
> filters to a 2013–2014 time window. These are the columns/format of the
> **New York City Taxi Fare Prediction** competition above. (The visually
> similar *NYC Taxi Trip Duration* competition has no `fare_amount` column and
> uses 2016 data, so it is **not** the source here.)

Suggested citation / acknowledgement:

```text
Will Cukierski, et al. "New York City Taxi Fare Prediction."
Kaggle, 2018. https://www.kaggle.com/competitions/new-york-city-taxi-fare-prediction
```

#### Weather data (`daily_weather_data_2009_2015.csv`)

Place this file in `Simulator/`. It is required by `load_data_with_map.py` and
`2014_data/TestData/combine_yellow_green_taxi.py`.

Fetch daily reanalysis for NYC (example coordinates: latitude `40.7128`,
longitude `-74.0060`) covering **2009-01-01 to 2015-12-31** via the
[Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api).
Request these **daily** variables and export a CSV with this header:

```text
date,temperature_2m_max,temperature_2m_min,temperature_2m_mean,rain_sum,snowfall_sum,daylight_duration,sunshine_duration
```

Example API request (JSON response — convert `daily` fields to the CSV above):

```text
https://archive-api.open-meteo.com/v1/archive
  ?latitude=40.7128&longitude=-74.0060
  &start_date=2009-01-01&end_date=2015-12-31
  &daily=temperature_2m_max,temperature_2m_min,temperature_2m_mean,rain_sum,snowfall_sum,daylight_duration,sunshine_duration
  &timezone=America%2FNew_York
```

Suggested citation:

```text
Open-Meteo. Historical Weather API. https://open-meteo.com/en/docs/historical-weather-api
```

#### Taxi zone shapefile (`taxi_zones.zip`)

Download the **Taxi Zone Maps** shapefile from the
[NYC TLC Trip Record Data](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page)
page (look for the *Taxi Zone* / shapefile download link) and place it in
`Simulator/` as one of:

- `Simulator/taxi_zones.zip` (recommended), or
- `Simulator/taxi_zones/taxi_zones.shp` (extracted archive)

The shapefile must include columns `LocationID`, `borough`, and `zone`. Both
`load_data_with_map.py` and `combine_yellow_green_taxi.py` resolve these paths
automatically.

Suggested citation:

```text
NYC Taxi & Limousine Commission. Taxi Zone Maps (shapefile).
https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page
```

## Layout

```
Simulator/
├── __init__.py                       # package API (re-exports the serving functions)
├── load_data_with_map.py             # raw Kaggle CSV -> processed feature CSV
├── beta_simulator.py                 # train logistic acceptance model(s)
├── simulator_response.py             # load artifacts + simulate accept/reject
├── requirements.txt
├── daily_weather_data_2009_2015.csv  # download from Open-Meteo (not in repo)
├── taxi_zones.zip                    # download from NYC TLC (not in repo)
└── beta_sensitivity_outputs_2013_4/  # pre-trained artifacts (per scenario)
    ├── scenario_summary.csv
    └── <scenario>/                   # e.g. pair_1p5_2p0__noise_05
        ├── beta_simulator_parameters.csv          # intercept + coefficients
        ├── beta_simulator_scaler.joblib           # fitted StandardScaler
        ├── beta_simulator_scaled_features_list.json
        └── metadata.json
```

Available pre-trained scenarios under `beta_sensitivity_outputs_2013_4/`:
`pair_1p5__noise_05`, `pair_1p2_1p5__noise_05`, `pair_1p5_2p0__noise_05`,
`pair_1p5_2p0__noise_10`, `pair_1p5_2p0__noise_20`. Each scenario folder
contains its own `beta_simulator_parameters.csv` (intercept + coefficients).

The repository ships these **pre-trained artifacts** under
`beta_sensitivity_outputs_2013_4/` so you can use the simulator **without
downloading the raw Kaggle data**. You only need the raw data if you want to
rebuild the processed dataset or retrain.

## Installation

```bash
pip install -r Simulator/requirements.txt
```

The geo dependencies (`geopandas`, `osmnx`, `haversine`) are only required by
`load_data_with_map.py`. If you just use the pre-trained artifacts, the core
packages (`numpy`, `pandas`, `scikit-learn`, `joblib`, `tqdm`) are enough.

## Usage

### 1. Use the pre-trained simulator (no raw data needed)

The package exposes its API via relative imports. Run from the **repository
root** so that `Simulator` is importable as a package; the artifacts are loaded
with a **relative path** (`base_dir` + `scenario_name`):

```python
from Simulator import (
    load_beta_simulator,
    load_scaler_and_features,
    simulate_passenger_acceptance,
)

scenario = "pair_1p5_2p0__noise_05"
# Relative path to the per-scenario folder holding beta_simulator_parameters.csv
root = "Simulator/beta_sensitivity_outputs_2013_4"

beta = load_beta_simulator(scenario_name=scenario, base_dir=root)
scaler, scaled_features = load_scaler_and_features(scenario_name=scenario, base_dir=root)

trip_features = {
    "distance_mi": 5.5,
    "passenger_count": 1,
    "pickup_in_manhattan": 1,
    "dropoff_in_manhattan": 1,
    "traffic_congestion": 1,
    # ... remaining contextual features default to 0 if omitted
}

accepted = simulate_passenger_acceptance(
    price_offered=20.0,
    trip_features_dict=trip_features,
    beta_simulator=beta,
    scaler=scaler,
    scaled_feature_names_list=scaled_features,
)
print("accepted" if accepted == 1 else "rejected")
```

You can also point at a scenario via the `BETA_SIMULATOR_DIR` environment
variable instead of passing `base_dir`/`scenario_name`.

### 2. Rebuild the processed dataset (needs raw Kaggle data + geo deps)

```bash
# Place train.csv (or train.csv.zip) in Simulator/ first.
python Simulator/load_data_with_map.py
# -> writes Simulator/2013_4_Trained_nyc_taxi_data_with_directionality.csv
```

This step time-filters to the **2013-12-01 to 2014-11-30** window, merges
weather, performs a taxi-zone spatial join, engineers temporal / distance /
directionality features, removes anomalies, and exports the selected feature
columns.

### 3. Retrain the acceptance model(s)

```bash
# Default: --processed-data-path and --output-root already point at the
# 2013_4 dataset / output folder, so this is equivalent to the explicit form below.
python Simulator/beta_simulator.py \
    --processed-data-path Simulator/2013_4_Trained_nyc_taxi_data_with_directionality.csv \
    --output-root Simulator/beta_sensitivity_outputs_2013_4

# Full grid of scenarios × noise rates
python Simulator/beta_simulator.py --scenario-set full --noise-rates 0.00,0.05,0.10
```

Each scenario writes `beta_simulator_parameters.csv`, the scaler, the scaled-
feature list, and `metadata.json` into `--output-root/<scenario>/`.

## Notes / reproducibility

- Random behaviour is controlled by `--seed` (default `2025`) in
  `beta_simulator.py`. Acceptance sampling in `simulate_passenger_acceptance`
  uses NumPy's global RNG; seed it (`np.random.seed(...)`) for reproducible draws.
- `beta_simulator.py`'s default `--processed-data-path` points at
  `2013_4_Trained_nyc_taxi_data_with_directionality.csv` (the output of
  `load_data_with_map.py`) and `--output-root` defaults to
  `beta_sensitivity_outputs_2013_4/`. Pass these flags to use different paths.
- The trained artifacts (one `beta_simulator_parameters.csv` plus scaler /
  feature-list / metadata per scenario) live under
  `beta_sensitivity_outputs_2013_4/<scenario>/` and are referenced by relative path.
- The large processed CSVs and the raw Kaggle data are git-ignored (see the
  repository `.gitignore`); only the small trained artifacts are tracked.
